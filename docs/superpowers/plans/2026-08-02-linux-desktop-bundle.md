# Linux Desktop Bundle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make CI produce an installable Linux `.deb` — a runnable application — alongside the Burrito sidecar it already builds.

**Architecture:** Five new steps appended to the existing `desktop` matrix job in `.github/workflows/ci.yml`, gated to x86_64 on pushes to main. `mix ex_tauri.build --ci --bundles deb` does the work; a `scripts/verify-deb.sh` shared by CI and a laptop asserts the result. Two supporting changes make the output correct: `tauri.conf.json` gains the runtime dependencies the .deb would otherwise omit entirely, and the project's four version declarations are aligned and guarded by a step in `mix check`.

**Tech Stack:** GitHub Actions, Elixir/Mix, Tauri 2 CLI (`cargo-tauri` 2.11.4), Burrito, `dpkg-deb`, POSIX `sh`.

**Spec:** `docs/superpowers/specs/2026-08-02-linux-desktop-bundle-design.md`. Section references below (§N) point there.

## Global Constraints

- **Never cross-compile.** Each arch builds on its own runner. Do not add `--target` to any build command.
- **`deploy` keeps `needs: [check]`.** Do not add the desktop job as a dependency of `deploy`.
- **The sidecar artifact upload stays.** The bundle is additional, not a replacement. The existing `Build the Burrito release`, `Verify the binary is present and native` and `upload-artifact` steps remain unconditional and unchanged.
- **Extend the existing `desktop` job.** Do not add a new job.
- **`bundle.targets` in `tauri.conf.json` stays `"all"`.** Narrowing happens via the `--bundles` CLI argument, so a local macOS build still produces `.app` and `.dmg`.
- **Never run `mix ex_tauri.install`,** in CI or while implementing. It regenerates `src-tauri/src/main.rs` and discards the hand-injected `ARMCHAIR_DESKTOP=1`.
- **The product version is `0.1.0`** and must read identically in all four sites: `mix.exs`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`.
- **Tauri CLI pinned at `2.11.4`** in the workflow.
- **Comment style:** this repository's `ci.yml` and `mix.exs` carry long comments that explain *why*, name the file and line of upstream behaviour they rely on, and record what was measured. Match that. A comment that only restates the code is noise here.
- **Every assertion must be shown to fail.** A check that passes because it is doing nothing looks identical to one that is satisfied — see §12 and `docs/superpowers/2026-07-30-follow-ups.md`.

## Implementation decision beyond the spec's letter

§12 requires each `.deb` assertion be shown to fail. The spec describes them as living in a "Verify the .deb" step. **This plan puts them in `scripts/verify-deb.sh` instead**, called by that step. The reason is arithmetic: mutating an inline CI step means four pushes to main, each a ~10-minute run and a production deploy. Mutating a script against a downloaded artifact costs nothing and can be done on a laptop. It also matches the repository's existing preference for one definition a laptop and a runner both run (`mix check`, `.sobelow-conf`, `src-tauri/.cargo/audit.toml`).

Cost: one new file, and `dpkg-deb` becomes a local dev dependency (`brew install dpkg`) for anyone running the verification by hand. CI needs nothing — `dpkg-deb` is present on Ubuntu.

### Task 1: Guard the version, then align it

**Files:**
- Modify: `mix.exs` (add four private functions; add one entry to the `check:` alias at ~line 493)
- Modify: `src-tauri/Cargo.toml:3`
- Modify: `src-tauri/Cargo.lock` (via cargo, not by hand)

**Interfaces:**
- Consumes: nothing.
- Produces: `mix check` fails unless all four version sites agree. Later tasks assume `0.1.0` everywhere.

This task is genuinely test-first: the check is written before the fix, and the first run fails against a real pre-existing drift rather than a contrived one.

- [ ] **Step 1: Add the version check to `mix.exs`**

Add these four private functions. Put them immediately after `host_burrito_target/0` (~line 260), which is where the other build-tooling helpers live.

```elixir
  # Every place this project stores its own version, checked as one number.
  #
  # They drift silently because each feeds a different consumer and no build step
  # consults more than one: `mix.exs` names Burrito's payload cache directory,
  # `tauri.conf.json` names the .deb and its control `Version:` field, `Cargo.toml` is
  # the fallback Tauri takes when `tauri.conf.json` omits `version`
  # (crates/tauri-cli/src/interface/rust.rs:1093), and `Cargo.lock` is what `cargo audit`
  # reads. This found a real drift the day it was written: the two Cargo files said
  # 0.2.0 while the two that actually ship said 0.1.0.
  #
  # A step in `mix check` rather than a git hook, deliberately. `.githooks/pre-push` is
  # a wrapper around `mix check` and nothing else, so this is picked up by that hook AND
  # by CI, which runs the same alias. A hook-only check would be a gate no runner sees.
  #
  # Only the *product's* version belongs here. The tool versions in `config/config.exs`
  # (Tauri CLI, tailwind, daisyui) and in the workflow (Elixir, OTP, Zig) are unrelated
  # numbers, and a check that cries wolf gets bypassed as a reflex.
  defp check_versions(_args) do
    sites = [
      {"mix.exs", Mix.Project.config()[:version]},
      {"src-tauri/tauri.conf.json", tauri_conf_version()},
      {"src-tauri/Cargo.toml", cargo_toml_version()},
      {"src-tauri/Cargo.lock", cargo_lock_version()}
    ]

    # Before comparing: a site that could not be read is nil, and four nils compare
    # equal. Without this clause a renamed file or an extractor whose pattern stopped
    # matching would make this check pass while reading nothing at all.
    case Enum.filter(sites, fn {_file, version} -> is_nil(version) end) do
      [] ->
        :ok

      unreadable ->
        Mix.raise("""
        Could not read a version from #{Enum.map_join(unreadable, ", ", &elem(&1, 0))}.

        Either the file is missing, or its format changed and the extractor in mix.exs
        needs updating. This is deliberately fatal: a version check that silently reads
        nothing passes forever.
        """)
    end

    case sites |> Enum.map(&elem(&1, 1)) |> Enum.uniq() do
      [agreed] ->
        Mix.shell().info("[versions] #{agreed}")

      _ ->
        Mix.raise("""
        Version declarations disagree.

        #{Enum.map_join(sites, "\n", fn {f, v} -> "  #{String.pad_trailing(f, 28)} #{v}" end)}

        All four must carry the same value. After editing src-tauri/Cargo.toml,
        regenerate the lock rather than editing it:

            cd src-tauri && cargo update --offline -p #{Mix.Project.config()[:app]}
        """)
    end
  end

  # OTP's own JSON decoder rather than Jason: this runs as the *first* step of the
  # `check` alias, before any task has put the dependencies' beam files on the code
  # path. `:json` is stdlib from OTP 27, which is this project's floor.
  defp tauri_conf_version do
    with {:ok, body} <- File.read("src-tauri/tauri.conf.json"),
         {:ok, %{"version" => version}} <- decode_json(body) do
      version
    else
      _ -> nil
    end
  end

  defp decode_json(body) do
    {:ok, :json.decode(body)}
  rescue
    _ -> :error
  end

  # A regex rather than a TOML dependency, to read one field from two cargo-generated
  # files whose formatting is stable. Anchored to the `[package]` table and stopped at
  # the next table header, so a dependency's own `version = ` cannot match. Returns nil
  # rather than a wrong answer if the shape ever changes, and nil is fatal above.
  defp cargo_toml_version do
    with {:ok, body} <- File.read("src-tauri/Cargo.toml"),
         [_, package_table] <- Regex.run(~r/^\[package\]\n(.*?)(?=^\[|\z)/ms, body),
         [_, version] <- Regex.run(~r/^version\s*=\s*"([^"]+)"/m, package_table) do
      version
    else
      _ -> nil
    end
  end

  defp cargo_lock_version do
    app = Mix.Project.config()[:app]

    with {:ok, body} <- File.read("src-tauri/Cargo.lock"),
         [_, version] <- Regex.run(~r/name = "#{app}"\nversion = "([^"]+)"/, body) do
      version
    else
      _ -> nil
    end
  end
```

Then add the capture as the first entry of the `check:` alias. Find:

```elixir
      check: [
        "format --check-formatted",
```

Replace with:

```elixir

        # makes for putting the security checks ahead of the suite applies with more
        # force to something this cheap.

        "format --check-formatted",
```

Finally run `mix format` — the alias runs `format --check-formatted` immediately after this new step, so unformatted code would fail there instead and mask the real result.

```bash

```

- [ ] **Step 6: Mutation-sweep all four sites**

One mutation is not enough. If only one site is really read, a single mutation still turns the check red and the other three go unverified — the exact pattern this codebase has hit repeatedly. Each site gets its own mutation, and the failure is matched by message so an unrelated failure cannot be mistaken for success.

```bash
set -e
for site in mix.exs src-tauri/tauri.conf.json src-tauri/Cargo.toml src-tauri/Cargo.lock; do
  cp "$site" "/tmp/$(basename "$site").bak"
  case "$site" in
    mix.exs)                   perl -0pi -e 's/version: "0\.1\.0"/version: "9.9.9"/' "$site" ;;
    src-tauri/tauri.conf.json) perl -0pi -e 's/"version": "0\.1\.0"/"version": "9.9.9"/' "$site" ;;
    src-tauri/Cargo.toml)      perl -0pi -e 's/(\[package\]\nname = "armchair_metropolist"\nversion = )"0\.1\.0"/${1}"9.9.9"/' "$site" ;;
    src-tauri/Cargo.lock)      perl -0pi -e 's/(name = "armchair_metropolist"\nversion = )"0\.1\.0"/${1}"9.9.9"/' "$site" ;;
  esac
  if mix check 2>&1 | grep -q 'Version declarations disagree'; then
    echo "ok: $site is read"
  else
    echo "MUTATION SURVIVED: $site is not read by check_versions/1"
    cp "/tmp/$(basename "$site").bak" "$site"; exit 1
  fi
  cp "/tmp/$(basename "$site").bak" "$site"
done
echo "all four sites verified"
```

Expected: four `ok:` lines then `all four sites verified`. Any `MUTATION SURVIVED` means that extractor is broken.

### Task 3: A .deb verification script that runs on a laptop too

**Files:**
- Create: `scripts/verify-deb.sh`

**Interfaces:**
- Consumes: a `.deb` produced by Task 2's config.
- Produces: `scripts/verify-deb.sh <bundle-dir>` — exits 0 if every assertion holds, non-zero with a `::error::` annotation otherwise. `<bundle-dir>` defaults to `src-tauri/target/release/bundle`. Task 4's workflow step calls it with that path.

- [ ] **Step 1: Write the script**

```sh
#!/bin/sh
# Every assertion about the .deb that `mix ex_tauri.build --bundles deb` produces.
#
# A script rather than inline workflow steps, because §12 of
# docs/superpowers/specs/2026-08-02-linux-desktop-bundle-design.md requires each
# assertion be *shown to fail*, and doing that inline would mean four pushes to main —
# four ~10-minute runs and four production deploys. Mutating this file against a
# downloaded artifact costs nothing. It also follows the same rule as `mix check` and
# src-tauri/.cargo/audit.toml: one definition a laptop and a runner both run.
#
#   Usage: scripts/verify-deb.sh [bundle-dir]
#   macOS: brew install dpkg   (CI needs nothing; Ubuntu ships dpkg-deb)

set -eu

BUNDLE_DIR="${1:-src-tauri/target/release/bundle}"

fail() {
  # ::error:: is a GitHub annotation; harmless noise in a terminal.
  printf '::error::%s\n' "$1" >&2
  exit 1
}

command -v dpkg-deb >/dev/null 2>&1 \
  || fail "dpkg-deb not found (macOS: brew install dpkg)"

# 1. A .deb exists. On failure, print the tree — the first run on Linux is the only
#    thing that establishes where Tauri actually puts it.
DEB=$(find "$BUNDLE_DIR/deb" -type f -name '*.deb' 2>/dev/null | head -1)
if [ -z "$DEB" ]; then
  ls -R "$BUNDLE_DIR" 2>/dev/null || echo "($BUNDLE_DIR does not exist)"
  fail "no .deb under $BUNDLE_DIR/deb"
fi
printf 'bundle:  %s (%s)\n' "$DEB" "$(du -h "$DEB" | cut -f1)"

# 2. Nothing else was built. A stray appimage/ or rpm/ means --bundles deb was ignored,
#    which would silently reintroduce AppImage's five build-time downloads — two of them
#    from an unpinned master branch.
for unwanted in appimage rpm; do
  [ ! -d "$BUNDLE_DIR/$unwanted" ] \
    || fail "--bundles deb did not take: $BUNDLE_DIR/$unwanted exists"
done

# 3. The package declares its runtime dependencies. Tauri writes no Depends: field
#    unless tauri.conf.json supplies one (debian.rs:204), and a .deb declaring nothing
#    installs onto a machine with no WebKit and then dies at the dynamic linker. This is
#    the standing regression test for that.
# A bare VAR=$(cmd) propagates cmd's exit status under set -e, which would abort here
# without the ::error:: annotation if dpkg-deb itself errored (as opposed to succeeding
# with an empty field, which the next line already handles).
DEPENDS=$(dpkg-deb --field "$DEB" Depends) || fail "dpkg-deb --field failed reading $DEB"
[ -n "$DEPENDS" ] || fail "the .deb declares no Depends"
printf 'Depends: %s\n' "$DEPENDS"

# 4. The Burrito sidecar is inside. A bundle without it is an empty window. Tauri strips
#    the target triple from externalBin entries — on macOS the file lands as
#    Contents/MacOS/desktop — so the *name* is asserted and the directory is not, because
#    the Linux path is not yet known.
if ! dpkg-deb --contents "$DEB" | awk '{print $NF}' | grep -qE '(^|/)desktop$'; then
  dpkg-deb --contents "$DEB"
  fail "the Burrito sidecar (a file named 'desktop') is not inside the .deb"
fi

# 5. Observed rather than asserted: proves at runtime that tauri.conf.json is the version
#    authority and src-tauri/Cargo.toml is the fallback Tauri never takes.
printf 'Version: %s\n' "$(dpkg-deb --field "$DEB" Version)"

printf '\n\033[32m✓ .deb verified\033[0m\n'
```

```

      # ---------------------------------------------------------------------------
      # The bundle. Everything below produces a runnable Linux application; everything
      # above produces the sidecar it wraps.
      #
      # The sidecar steps stay unconditional and first on purpose. `mix ex_tauri.build`
      # re-runs `mix release desktop` internally (ExTauri.wrap/1, deps/ex_tauri/lib/
      # ex_tauri.ex:241), so this duplicates ~69s of Burrito work on this one path. That
      # is the price of a wrapper failure never being able to take the sidecar's arch
      # check and artifact down with it — the sidecar is green on both arches today and
      # the Linux wrapper build is unproven.
      # ---------------------------------------------------------------------------

      # Derived from src-tauri/Cargo.lock, not copied from Tauri's prerequisites page,
      # which is a union across all Tauri projects. Reading every
      # [package.metadata.system-deps] table and pkg_config probe in the 338-crate Linux
      # tree gives exactly these three, and differs from that page four ways:
      # libxdo-dev is unnecessary (no xdo crate anywhere), libayatana-appindicator3-dev
      # is unnecessary at build time (libappindicator-sys 0.9 has no build.rs — it
      # dlopens the library), libssl-dev is unnecessary (no openssl-sys), and
      # libdbus-1-dev is REQUIRED but absent from that page: tao pulls libdbus-sys, which
      # probes dbus-1 with plain pkg_config. That omission is the dangerous direction —
      # it surfaces hundreds of crates into a release build.
      - name: Install the GTK and WebKit development headers
        if: env.BUNDLE == 'true'
        run: |
          sudo apt-get update
          sudo apt-get install -y --no-install-recommends \
            libwebkit2gtk-4.1-dev libgtk-3-dev libdbus-1-dev

      # NOT `mix ex_tauri.install`. That is the supported way to get this binary and the
      # wrong one here: it is Igniter-driven and regenerates src-tauri/src/main.rs from a
      # template, discarding the hand-injected ARMCHAIR_DESKTOP=1 that every desktop
      # config override keys off (docs/superpowers/2026-07-30-follow-ups.md, "Desktop
      # release env staleness"). This does the one thing that installer does which CI
      # needs: put a binary where ExTauri's `tauri_cli_path!()` looks for it.
      #
      # A prebuilt binary rather than `cargo install tauri-cli`, which compiles for
      # minutes. Pinned rather than following config/config.exs's floating `^2.5.1`: a
      # runner should be reproducible where a laptop may float. Bump this when that pin
      # moves. Note the asset only exists for x86_64 and riscv64gc — there is no
      # aarch64-unknown-linux-gnu build, which is half the reason for the arch gate above.
      #
      # Deliberately not guarded with `test -x`: _build is cached, and a guard would let
      # a CLI left by an older pin survive this bump silently.
      - name: Install the Tauri CLI
        if: env.BUNDLE == 'true'
        env:
          TAURI_CLI_VERSION: "2.11.4"
        run: |
          mkdir -p _build/_tauri/bin
          curl -fsSL -o /tmp/cargo-tauri.tgz \
            "https://github.com/tauri-apps/tauri/releases/download/tauri-cli-v${TAURI_CLI_VERSION}/cargo-tauri-x86_64-unknown-linux-gnu.tgz"
          tar -xzf /tmp/cargo-tauri.tgz -C _build/_tauri/bin cargo-tauri
          _build/_tauri/bin/cargo-tauri --version

      # `--bundles deb` narrows tauri.conf.json's `"targets": "all"`, which on Linux would
      # also build rpm and AppImage. AppImage's bundler downloads five artefacts during
      # the build (appimage/linuxdeploy.rs), two of them from an unpinned `master` branch,
      # so it can break with no change to this repository and no advisory to explain it.
      # The config keeps "all" so a local macOS build still produces .app and .dmg.
      - name: Build the Linux bundle
        if: env.BUNDLE == 'true'
        run: mix ex_tauri.build --ci --bundles deb

      # The same script a laptop runs against a downloaded artifact — see its header for
      # why the assertions live there rather than inline here.
      - name: Verify the .deb
        if: env.BUNDLE == 'true'
        run: ./scripts/verify-deb.sh src-tauri/target/release/bundle

      - name: Upload the Linux bundle
        if: env.BUNDLE == 'true'
        uses: actions/upload-artifact@v7
        with:
          name: desktop-bundle-${{ matrix.target }}
          path: src-tauri/target/release/bundle/deb/*.deb
          if-no-files-found: error
          retention-days: 14
```

- [ ] **Step 6: Mutation-sweep the verification script**

Each assertion mutated on its own, against the real artifact, so a survivor identifies exactly which one is inert.

```bash
set -e
cp scripts/verify-deb.sh /tmp/verify-deb.sh.bak

check() { # $1 = label
  if ./scripts/verify-deb.sh /tmp/fake-bundle >/dev/null 2>&1; then
    echo "MUTATION SURVIVED: $1"; cp /tmp/verify-deb.sh.bak scripts/verify-deb.sh; exit 1
  else
    echo "ok: $1 bites"
  fi
  cp /tmp/verify-deb.sh.bak scripts/verify-deb.sh
}

# 1. the .deb-exists gate
perl -0pi -e "s/-name '\*\.deb'/-name '*.NOPE'/" scripts/verify-deb.sh
check "a .deb exists"

# 2. the sidecar-inside gate
perl -0pi -e "s/desktop\\\$'/nosuchbinary\$'/" scripts/verify-deb.sh
check "the sidecar is inside"

# 3. the Depends gate — mutate the input, not the script, since an empty Depends is
#    what the real regression looks like
perl -0pi -e 's/\[ -n "\$DEPENDS" \]/[ -z "$DEPENDS" ]/' scripts/verify-deb.sh
check "Depends is non-empty"

# 4. the stray-bundle gate
mkdir -p /tmp/fake-bundle/appimage
if ./scripts/verify-deb.sh /tmp/fake-bundle >/dev/null 2>&1; then
  echo "MUTATION SURVIVED: stray appimage/ not detected"; rmdir /tmp/fake-bundle/appimage; exit 1
else
  echo "ok: stray appimage/ bites"
fi
rmdir /tmp/fake-bundle/appimage

./scripts/verify-deb.sh /tmp/fake-bundle >/dev/null && echo "and the unmutated script still passes"
```

Expected: four `ok:` lines, then `and the unmutated script still passes`. That last line matters — without it, a red result could mean the script is simply broken rather than that the mutation was caught.
